## 2. 系统初始化流程

### 2.1 调用链

```
main()
  -> system_init()       // 硬件和文件系统初始化
  -> OSInit()            // UCOSII初始化
  -> OSTaskCreateExt()   // 创建start_task
  -> OSStart()           // 启动操作系统
```

### 2.2 system_init() 详细初始化顺序

该函数的顺序极其重要，不能随意调整，以下是完整的初始化序列：

```c
// ===== 第1步：时钟与基础外设 =====
sys_stm32_clock_init(160,5,2,4);    // 设置时钟，400MHz
    // 参数说明: PLL_N=160, PLL_P=5, PLL_Q=2, PLL_R=4
delay_init(400);                    // 延时初始化（基于400MHz）
exeplay_app_check();                // 检查是否需要运行APP代码（IAP功能）
usart_init(100,115200);             // 串口1初始化（调试串口）
usart3_init(100,115200);            // 串口3初始化（GSM通信串口）
usmart_dev.init(200);               // USMART调试组件初始化

// ===== 第2步：GPIO与存储保护 =====
led_init();                         // LED初始化
mpu_memory_protection();            // MPU保护配置（7个区域）

// ===== 第3步：外部存储 =====
sdram_init();                       // SDRAM初始化（32MB, FMC BANK5）
    // 详细配置见第5节

// ===== 第4步：显示 =====
lcd_init();                         // LCD初始化（自动识别MCU屏/RGB屏）

// ===== 第5步：输入设备 =====
key_init();                         // 按键初始化

// ===== 第6步：板载外设存储芯片 =====
at24cxx_init();                     // AT24C02 EEPROM初始化
norflash_init();                    // W25Q256 SPI Flash初始化

// ===== 第7步：ADC =====
adc_init();                         // ADC1初始化（采集外部ADC值）
adc3_init();                        // ADC3初始化（内部温度传感器）

// ===== 第8步：IO扩展 =====
pcf8574_init();                     // PCF8574 IO扩展芯片初始化（控制蜂鸣器等）

// ===== 第9步：内存池 =====
my_mem_init(SRAMIN);                // 内部SRAM内存池
my_mem_init(SRAMEX);                // 外部SDRAM内存池
my_mem_init(SRAM12);                // SRAM1+SRAM2内存池
my_mem_init(SRAM4);                 // SRAM4内存池
my_mem_init(SRAMDTCM);              // DTCM内存池
my_mem_init(SRAMITCM);              // ITCM内存池

// ===== 第10步：触摸屏 =====
tp_dev.init();                      // 触摸屏初始化

// ===== 第11步：GUI系统 =====
gui_init();                         // GUI初始化
piclib_init();                      // 图片库初始化
slcd_dma_init();                    // SLCD DMA初始化

// ===== 第12步：USB与文件系统 =====
usbapp_init();                      // USB应用初始化
exfuns_init();                      // FATFS申请内存

// ===== 第13步：硬件自检（逐项检测，失败则显示错误） =====
// 检测顺序：
//   ES8388（音频芯片） -> 外部SRAM -> NAND Flash -> SPI Flash
//   -> RTC -> FatFS挂载 -> SD卡 -> SPI Flash文件系统
//   -> NAND文件系统 -> U盘 -> TPAD(触摸按键)
//   -> PCF8574 -> AP3216C(光感) -> 24C02 -> ES8388
//   -> SH3001(IMU) -> 字库检测 -> 系统文件检测
//   -> 触摸屏校准 -> 系统参数加载
```

### 2.3 硬件自检详细流程

```
system_init() 中后续的自检代码逻辑：

1. 显示版权信息（ALIENTEK LOGO + 版本号 + LCD ID）
2. LED0+LED1同时点亮，然后熄灭
3. 显示CPU型号：STM32H743IIT6 400Mhz
4. 显示内部存储：FLASH:2048KB  SRAM:1060KB
5. 外部SDRAM检测：system_exsram_test()
   - 在32MB空间内每隔32KB写入一个递增数据
   - 再读出校验，计算容量
   - 检测后需要重新初始化内存池：my_mem_init(SRAMEX)
6. NAND Flash检测：nand_init()
7. SPI Flash检测：norflash_read_id() 判断是否为W25Q256
8. 开机时如果按下WKUP键：擦除SPI Flash内容
9. RTC检测：rtc_init() -> calendar_get_time/date()
10. FatFS挂载：
    - f_mount(fs[0], "0:", 1)   // SD卡
    - f_mount(fs[1], "1:", 1)   // SPI Flash
    - f_mount(fs[2], "2:", 1)   // NAND Flash
11. SD卡容量检测：exfuns_get_free("0:", ...)，最多重试5次
12. SPI Flash文件系统检测：exfuns_get_free("1:", ...)
    - 如果文件系统不存在(f_mkfs返回0x0D)：格式化 + 设置卷标
13. NAND文件系统检测：同SPI Flash
14. U盘检测：
    - 设置USB模式为MSC
    - 等待最多8秒检测U盘
    - 如果1.5秒内没有插入则跳过
15. TPAD触摸按键检测：tpad_init(2)
    - 失效标记：g_tpad_failed_flag = 1（用WK_UP替代）
16. PCF8574检测
17. AP3216C光感检测（不阻塞）
18. 24C02检测（阻塞）
19. ES8388音频芯片检测（阻塞）
20. SH3001 IMU检测（不阻塞）
21. 字库检测：fonts_init()
    - 如果不存在或按KEY1：从SD卡更新 -> 从U盘更新
22. 系统文件检测：app_system_file_check("1")
    - 从SD卡或U盘更新系统文件到SPI Flash
23. 触摸屏校准：tp_init()
    - 按KEY0触发校准（电阻屏）
24. 系统参数加载：app_system_parameter_init()
    - 从EEPROM(24C02)地址100处加载系统参数
```

## 3. UCOSII任务架构

### 3.1 任务一览表

| 任务名 | 函数 | 优先级 | 栈大小 | 功能 |
|--------|------|--------|--------|------|
| start_task | start_task(void *pdata) | 10(最低) | 128 | 创建其他任务后挂起自身 |
| main_task | main_task(void *pdata) | 6 | 1200 | 主任务，运行SPB界面和应用 |
| usart_task | usart_task(void *pdata) | 7 | 128 | 串口任务，低时效性代码 |
| watch_task | watch_task(void *pdata) | 3 | 256 | 监视任务，系统状态监控 |

### 3.2 start_task 创建流程

```c
void start_task(void *pdata)
{
    OSStatInit();                           // 初始化统计任务
    // 配置SysTick节拍频率：(400 * 1000000) / OS_TICKS_PER_SEC
    OS_CPU_SysTickInit(cnts);
    app_srand(OSTime);                      // 随机数种子
    audiombox = OSMboxCreate((void *)0);    // 创建音频邮箱

    OS_ENTER_CRITICAL();                    // 临界区
    // 创建 main_task（优先级6）
    // 创建 usart_task（优先级7）
    // 创建 watch_task（优先级3）
    OSTaskSuspend(START_TASK_PRIO);         // 挂起自身
    OS_EXIT_CRITICAL();
}
```

所有任务创建时均使用 `OS_TASK_OPT_STK_CHK | OS_TASK_OPT_STK_CLR | OS_TASK_OPT_SAVE_FP` 选项，确保：
- 栈检查功能开启
- 栈清零
- 浮点寄存器保存（防止浮点运算异常）

### 3.3 main_task 主循环

```c
void main_task(void *pdata)
{
    spb_init(0);            // 初始化SPB主界面（3页x8图标）
    spb_load_mui();         // 加载SPB主界面资源
    slcd_frame_show(spbdev.spbahwidth);  // 显示帧

    while (1) {
        selx = spb_move_chk();          // 检测触摸/滑动，返回双击的图标索引
        system_task_return = 0;         // 清退出标志

        switch (selx) {                 // 根据图标索引分发到28个应用
            case 0: ebook_play(); break;
            case 1: picviewer_play(); break;
            // ... 共计28个case
            case SPB_ICOS_NUM: phone_play(); break;      // 24
            case SPB_ICOS_NUM+1: app_play(); break;      // 25
            case SPB_ICOS_NUM+2: vmeter_play(); break;   // 26
        }

        if (selx != 0xFF) spb_load_mui(); // 刷新主界面
        delay_ms(1000 / OS_TICKS_PER_SEC);
        // 每500个节拍（约1秒）更新状态栏
        if (++tcnt == 500) {
            tcnt = 0;
            spb_stabar_msg_show(0);
        }
    }
}
```

### 3.4 usart_task 串口任务

```c
void usart_task(void *pdata)
{
    while (1) {
        delay_ms(1000);
        // 1. 闹钟响铃处理（最多5分钟自动关闭）
        // 2. 来电提醒（GSM模式3时）
        // 3. 自动背光控制（当systemset.lcdbklight == 0时）
        // 4. 打印内存使用率（当memshow_flag == 1时）
    }
}
```

### 3.5 任务退出机制

使用全局变量 `volatile uint8_t system_task_return`：
- 在watch_task中检测TPAD触摸按键或WK_UP按键
- 设 `system_task_return = 1` 表示请求退出当前应用
- 各应用在自己的主循环中检测此标志并返回

## 4. MPU内存保护配置

MPU配置由 `mpu_memory_protection()` 实现，在 `system_init()` 中调用（位于SDRAM初始化之后、LCD初始化之前）。

### 4.1 7个保护区域

| 区域 | 基地址 | 大小 | 编号 | Cache | Buffer | 用途 |
|------|--------|------|------|-------|--------|------|
| DTCM | 0x20000000 | 128KB | 1 | 允许 | 允许 | 内部DTCM数据 |
| AXI SRAM | 0x24000000 | 512KB | 2 | 允许 | 允许 | 内部AXI SRAM |
| SRAM1~3 | 0x30000000 | 512KB | 3 | 允许 | 允许 | 内部SRAM1-3 |
| SRAM4 | 0x38000000 | 64KB | 4 | 允许 | 允许 | 内部SRAM4 |
| FMC LCD | 0x60000000 | 64MB | 5 | **禁止** | **禁止** | MCU屏FMC区域 |
| SDRAM | 0xC0000000 | 32MB | 6 | **禁止** | **禁止** | 外部SDRAM |
| NAND Flash | 0x80000000 | 256MB | 7 | **禁止** | **禁止** | NAND Flash |

### 4.2 关键注意事项

1. **FMC LCD区域（0x60000000）必须禁止Cache和Buffer**，否则MCU屏会显示异常
2. **SDRAM和NAND Flash也必须禁止Cache**，防止DMA/摄像头等外设数据不一致
3. 内部SRAM区域允许Cache以提升性能
4. 如果修改了存储映射，必须同步更新MPU配置

## 5. SDRAM配置

### 5.1 基本参数

| 参数 | 值 |
|------|-----|
| 起始地址 | 0xC0000000（FMC BANK5） |
| 容量 | 32MB |
| 时钟 | 110MHz（PLL2_R / 2 = 220M/2） |
| 数据位宽 | 16位 |
| 列地址 | 9位 |
| 行地址 | 13位 |
| Bank数量 | 4个 |
| CAS延迟 | 2 |
| 突发访问 | 使能 |

### 5.2 初始化步骤

```c
void sdram_init(void)
{
    // 1. 使能GPIO时钟（PC/PD/PE/PF/PG）+ FMC时钟
    RCC->AHB4ENR |= 0x1F << 2;
    RCC->AHB3ENR |= 1 << 12;

    // 2. 配置GPIO复用功能（AF12 = FMC）
    // PC0,2,3 / PD0,1,8,9,10,14,15 / PE0,1,7~15
    // PF0~5,11~15 / PG0~2,4,5,8,15

    // 3. 设置SDCR控制寄存器
    // 4. 设置SDTR时序寄存器
    // 5. 使能FMC
    FMC_Bank1_R->BTCR[0] |= (uint32_t)1 << 31;

    // 6. 发送初始化命令序列
    sdram_send_cmd(0, 1, 0, 0);     // 时钟配置使能
    delay_us(500);
    sdram_send_cmd(0, 2, 0, 0);     // 预充电
    sdram_send_cmd(0, 3, 8, 0);     // 自刷新（8次）
    sdram_send_cmd(0, 4, 0, mregval); // 加载模式寄存器
}
```

## 6. LCD显示系统

### 6.1 双模式支持

该系统同时支持两种LCD接口：

**MCU屏模式（FMC接口）**：
- 通过FMC驱动（类似于8080并口）
- 引脚：WR=PD5, RD=PD4, BL=PB5, CS=PD7(FMC_NE1), RS=PD13(FMC_A18)
- 数据线D0~D15通过FMC自动管理
- 地址映射：LCD->LCD_REG / LCD->LCD_RAM

**RGB屏模式（LTDC接口）**：
- 通过LTDC外设驱动
- 帧缓冲地址：0xC0000000（SDRAM起始）
- 支持多层显示
- 像素格式：RGB565

### 6.2 LCD初始化流程

```c
void lcd_init(void)
{
    // 1. 初始化GPIO（WR/RD/BL/CS/RS）
    // 2. 配置FMC（数据宽度16位，地址宽度16位）
    // 3. 读取LCD ID，根据ID选择:
    //    - 如果ID == 0，尝试LTDC(RGB屏)初始化
    //    - 否则按MCU屏ID匹配初始化序列
    //    - 支持的MCU屏IC: ILI9341/NT35310/NT35510/SSD1963/ST7789/ST7796/ILI9806
    // 4. 设置lcddev全局参数(width, height, id, dir等)
}
```

### 6.3 关键全局变量

```c
_lcd_dev lcddev;           // LCD设备参数
uint32_t g_point_color;    // 当前画笔颜色
uint32_t g_back_color;     // 当前背景色
```

## 7. 触摸屏系统

### 7.1 支持的触摸控制器

- 电阻屏：ADS7843/7846/UH7843/7846/XPT2046/TSC2046
- 电容屏：GT9147/GT9271/FT5206/GT1151

### 7.2 数据结构

```c
typedef struct {
    uint8_t (*init)(void);      // 初始化函数指针
    uint8_t (*scan)(uint8_t);   // 扫描函数指针
    void (*adjust)(void);       // 校准函数指针
    uint16_t x[CT_MAX_TOUCH];   // 最多10点触摸坐标
    uint16_t y[CT_MAX_TOUCH];
    uint16_t sta;               // b15:按下/松开, b14:按键按下
    float xfac, yfac;           // 电阻屏校准比例因子
    short xc, yc;               // 中心点坐标
    uint8_t touchtype;          // b0:横竖屏, b7:电阻/电容
} _m_tp_dev;

extern _m_tp_dev tp_dev;
```

### 7.3 触摸与退出机制（重要）

两个退出当前应用的方式：

1. **TPAD触摸按键退出**：
```c
if (tpad_scan(0)) {         // 检测到TPAD按下
    rerreturn = 10;         // 100ms内不允许再次触发
    system_task_return = 1;  // 设置退出标志
}
```

2. **TPAD失效时WK_UP按键替代**：
```c
if (g_tpad_failed_flag) {   // TPAD失效
    key = key_scan(0);
    if (key == WKUP_PRES) {
        system_task_return = 1;
    }
}
```

## 8. 文件系统（FatFs）配置

### 8.1 存储设备盘符映射

| 盘符 | 设备 | 物理接口 | FatFs对象 | 在位标记 |
|------|------|----------|-----------|----------|
| 0: | SD卡 | SDMMC | fs[0] | memdevflag bit0 |
| 1: | SPI Flash(W25Q256) | QSPI | fs[1] | memdevflag bit1 |
| 2: | NAND Flash | FMC | fs[2] | memdevflag bit2 |
| 3: | U盘 | USB HOST | fs[3] | memdevflag bit3 |

### 8.2 挂载流程

```c
// system_init() 中
f_mount(fs[0], "0:", 1);    // 挂载SD卡
f_mount(fs[1], "1:", 1);    // 挂载SPI FLASH文件系统
```

## 13. watch_task监控任务详解

watch_task（优先级3，最高优先级的应用任务）负责持续监控系统状态：

```c
void watch_task(void *pdata) {
    while (1) {
        // === 1. 闹钟消息显示 ===
        if (alarm.ringsta & 1 << 7)
            calendar_alarm_msg(...);

        // === 2. GIF解码时触摸检测 ===
        if (g_gif_decoding) {
            key = pic_tp_scan();
            if (key == 1 || key == 3) g_gif_decoding = 0;  // 停止GIF
        }

        // === 3. LED0心跳指示 ===
        // 每2.5秒亮100ms（仅当ledplay_ds0_sta == 0时）
        if (ledplay_ds0_sta == 0) {
            if (t == 4)   LED0(1);
            if (t == 119) { LED0(0); t = 0; }
        }
        t++;

        // === 4. TPAD退出检测 ===
        // 检测TPAD或WK_UP，设置system_task_return

        // === 5. 存储设备热插拔（每900ms） ===
        if ((t % 60) == 0) {
            // SD卡检测（摄像头不工作时）
            // U盘检测
            // GSM状态检测（lwip未启用时）
        }

        // === 6. GSM来电/短信监测 ===
        gsm_cmsgin_check();

        // === 7. USB Host处理 ===
        if (usbx.mode == USBH_MSC_MODE) {
            // 等待U盘连接稳定
            // 轮询USB事务
        }

        delay_ms(10);
    }
}
```

### 13.1 LED心跳机制

- LED0默认为系统心跳灯，每约2.5秒闪一次
- 如果某个应用需要独占LED0（如ledplay），设置 `ledplay_ds0_sta = 1` 禁用心跳
- 应用结束后恢复 `ledplay_ds0_sta = 0`

## 14. HardFault硬件错误处理

当发生HardFault时，通过串口打印关键寄存器：

```c
void HardFault_Handler(void) {
    temp = SCB->CFSR;   // Configurable Fault Status Register
    printf("CFSR:%8X\r\n", temp);
    temp = SCB->HFSR;   // HardFault Status Register
    printf("HFSR:%8X\r\n", temp);
    temp = SCB->DFSR;   // Debug Fault Status Register
    printf("DFSR:%8X\r\n", temp);
    temp = SCB->AFSR;   // Auxiliary Fault Status Register
    printf("AFSR:%8X\r\n", temp);

    // LED1闪烁5次后停止
    while (t < 5) { LED1(led1sta ^= 1); delay... }
}
```

常见HardFault原因分析：
- **CFSR[7] MMARVALID**：MPU访问违规（检查MPU配置区域是否正确）
- **CFSR[12] IBUSERR**：取指令总线错误（Flash/内存地址非法）
- **HFSR[30] FORCED**：其他fault升级导致（先检查CFSR）
- DFSR/AFSR通常为0（正常应用不使用调试功能）

```c
// SDMMC_CK = sdmmc_ker_ck / [2 * clkdiv]

#define SDMMC_INIT_CLK_DIV     250   // 初始化时：200M/(250*2)=400KHz (不能超过400KHz)
```

### C.2 SD卡初始化完整流程

```
sd_init()
│
├─ 1. 使能SDMMC1时钟：RCC->AHB3ENR |= 1 << 16
├─ 2. 使能6个GPIO时钟（PC8~PC12, PD2）
├─ 3. 配置GPIO为AF12复用、推挽输出、高速、上拉
├─ 4. SDMMC1硬件复位（RCC->AHB3RSTR）
├─ 5. SDMMC1外设寄存器清零
│
├─ 6. sdmmc_power_on() ───── 卡上电与类型识别
│   ├─ 配置CLKCR：1位模式、非省电、下降沿
│   ├─ 设置初始化时钟（400KHz）
│   ├─ POWER=0x03（上电+开时钟）
│   ├─ 循环发送CMD0（GO_IDLE_STATE）最多74次
│   ├─ 发送CMD8（SEND_IF_COND），带参数0x1AA
│   │   ├─ 有响应 → CardType = SD V2.0（高容量卡）
│   │   └─ 无响应 → CardType = SD V1.1
│   ├─ 发送CMD55+ACMD41（SD_APP_OP_COND）
│   │   ├─ 参数=0x80100000（支持2.7~3.6V）
│   │   ├─ 轮询等待bit31置位（上电完成）
│   │   └─ 如果响应bit30置位 → HIGH_CAPACITY_SD_CARD
│   └─ 如果不是SD卡，发送CMD1识别MMC卡
│
├─ 7. sdmmc_initialize_cards() ─ 卡初始化
│   ├─ 发送CMD2（ALL_SEND_CID）获取CID
│   ├─ 发送CMD3（SET_REL_ADDR）获取RCA
│   └─ 发送CMD9（SEND_CSD）获取CSD
│
├─ 8. sdmmc_get_card_info() ─ 解析卡信息
│   ├─ 从CSD解析卡类型、容量、块大小
│   ├─ 标准容量卡：CardCapacity = (DeviceSize+1) * (1<<(DeviceSizeMul+2)) * CardBlockSize
│   └─ 高容量卡：CardCapacity = (DeviceSize+1) * 512 * 1024, CardBlockSize = 512
│
├─ 9. sdmmc_select_deselect() ─ 选中SD卡（CMD7+RCA）
│
├─ 10. sdmmc_wide_bus_operation(1) ─ 切换到4位数据宽度
│    └─ 如果是MMC卡，跳过此步骤（MMC不支持4位模式）
│
└─ 11. 设置传输时钟（33.3MHz）：sdmmc_clock_set(SDMMC_TRANSFER_CLK_DIV)
```

### C.3 sd_read_disk() / sd_write_disk() — FatFs磁盘接口

这是FatFs文件系统调用SD卡的底层接口：

```c
uint8_t sd_read_disk(uint8_t *pbuf, uint32_t saddr, uint32_t cnt)
{
    long long lsaddr = saddr;
    // 关键：高容量SD卡使用字节地址，需要扇区号<<9
    if (CardType != STD_CAPACITY_SD_CARD_V1_1) lsaddr <<= 9;
    sta = sdmmc_read_blocks(pbuf, lsaddr, 512, cnt);
    return sta;
}

uint8_t sd_write_disk(uint8_t *pbuf, uint32_t saddr, uint32_t cnt)
{
    long long lsaddr = saddr;
    if (CardType != STD_CAPACITY_SD_CARD_V1_1) lsaddr <<= 9;
    sta = sdmmc_write_blocks(pbuf, lsaddr, 512, cnt);
    return sta;
}
```

**关键注意事项**：`long long lsaddr` 使用64位变量非常关键！因为SDHC/XC卡的地址是字节地址，32GB卡已经超过uint32_t范围。

### C.4 sdmmc_read_blocks() 读取流程（轮询模式）

```c
static SD_Error sdmmc_read_blocks(uint8_t *pbuf, long long addr,
                                   uint16_t blksize, uint32_t nblks)
{
    // 1. DCTRL清零（关闭DMA，使用轮询模式）
    SDMMC1->DCTRL = 0x0;

    // 2. 高容量卡：blksize固定512，地址是块地址
    if (CardType == HIGH_CAPACITY_SD_CARD) {
        blksize = 512;
        addr >>= 9;
    }

    // 3. 设置块大小：CMD16
    sdmmc_send_cmd(SD_CMD_SET_BLOCKLEN, 1, blksize);

    // 4. 配置数据传输参数
    sdmmc_send_data_cfg(SD_DATATIMEOUT, nblks * blksize, 9, 1);
    //   块大小=2^9=512字节，方向=卡到控制器

    // 5. 发送读命令
    if (nblks > 1)
        sdmmc_send_cmd(SD_CMD_READ_MULT_BLOCK, 1, addr);  // CMD18(多块)
    else
        sdmmc_send_cmd(SD_CMD_READ_SINGLE_BLOCK, 1, addr); // CMD17(单块)

    // 6. 轮询等待数据（关键循环）
    // sys_intx_disable();  // ⚠️ 原代码注释掉了！
    while (!(SDMMC1->STA & (RXOVERR | DCRCFAIL | DTIMEOUT | DATAEND))) {
        if (SDMMC1->STA & (1 << 15)) {     // FIFO半满（8个字=32字节）
            // 一次读取8个32bit字 = 32字节
            for (count = 0; count < 8; count++) {
                data = SDMMC1->FIFO;
                *tempbuff++ = (uint8_t)data;
                *tempbuff++ = (uint8_t)(data >> 8);
                *tempbuff++ = (uint8_t)(data >> 16);
                *tempbuff++ = (uint8_t)(data >> 24);
            }
            timeout = SDMMC_DATATIMEOUT;
        } else {
            if (timeout == 0) return SD_DATA_TIMEOUT;
            timeout--;
        }
    }
    // sys_intx_enable();

    // 7. 检查错误标志
    if (SDMMC1->STA & DTIMEOUT)  return SD_DATA_TIMEOUT;
    if (SDMMC1->STA & DCRCFAIL)  {
        if (nblks > 1) sdmmc_send_cmd(SD_CMD_STOP_TRANSMISSION, 1, 0); // CMD12
        return SD_DATA_CRC_FAIL;
    }
    if (SDMMC1->STA & RXOVERR)   return SD_RX_OVERRUN;

    // 8. 多块读结束后发送CMD12
    if (nblks > 1) sdmmc_send_cmd(SD_CMD_STOP_TRANSMISSION, 1, 0);

    SDMMC1->ICR = 0X1FE00FFF;  // 清除所有中断标志
    return SD_OK;
}
```

### C.5 SD卡关键Bug与排查

#### Bug 1：CRC错误（最常见）

**现象**：文件读取偶尔失败，FatFs返回CRC错误

**根因分析**：
1. **SDMMC时钟频率过高**：`SDMMC_TRANSFER_CLK_DIV = 3` 即 200M/(2*3)≈33.3MHz，部分TF卡无法稳定工作在此频率
2. **PCB布线质量问题**：长走线或没有等长设计的CLK/DATA线导致时序问题
3. **中断打断轮询**：原代码中 `sys_intx_disable()` 被注释掉了

**修复方案**：
```c
// 方案1：降低传输时钟
#define SDMMC_TRANSFER_CLK_DIV    6   // 200M/(2*6)≈16.7MHz，更稳定

// 方案2：在读取循环中关闭总中断（取消注释）
// 找到 sdmmc_sdcard.c 中的 sys_intx_disable()/sys_intx_enable()
// 取消注释即可

// 方案3：改用DMA模式
// 将 DCTRL 配置为DMA传输，但需要配置MDMA通道
```

#### Bug 2：SD卡热插拔导致死机

**现象**：运行中拔出SD卡，系统卡死或进入HardFault

**根因**：`sdmmc_get_status()` 在SD卡不在位时访问SDMMC寄存器导致超时，如果在非临界区调用可能被打断

**正确做法（参照watch_task）**：
```c
OS_ENTER_CRITICAL();
res = sdmmc_get_status();    // 必须在临界区中操作
OS_EXIT_CRITICAL();

if (res == 0xFF) {           // 返回0xFF表示卡不在位
    gui_phy.memdevflag &= ~(1 << 0);   // 标记SD卡不在位
    OS_ENTER_CRITICAL();
    sd_init();               // 重新初始化SD卡
    OS_EXIT_CRITICAL();
}
```

#### Bug 3：高容量卡地址转换错误

**现象**：SDHC/SDXC卡读写位置偏移，文件损坏

**根因**：高容量卡需要使用**字节地址**（扇区号*512），但代码中扇区号使用uint32_t，大于4GB时溢出

**正确代码**：
```c
// 正确：使用long long（64位）
long long lsaddr = saddr;
if (CardType != STD_CAPACITY_SD_CARD_V1_1) lsaddr <<= 9;

// 错误：使用uint32_t（32位）
uint32_t lsaddr = saddr;
if (CardType != STD_CAPACITY_SD_CARD_V1_1) lsaddr <<= 9;  // 可能溢出！
```

#### Bug 4：摄像头工作时无法检测SD卡

**现象**：拍照模式下SD卡状态检测异常

**根因**：watch_task中有保护逻辑：
```c
if ((DCMI->CR & 0X01) == 0) {  // 摄像头不工作时才检测
    // ... SD卡检测代码
}
```
DCMI和SDMMC存在总线竞争，摄像头工作时不应操作SD卡。

#### Bug 5：FIFO读取与超时逻辑

**根因**：轮询模式中，FIFO半满中断标志（bit15）的处理逻辑中，`timeout`变量在每次成功读取后重置，但如果在FIFO等待期间有长时间中断，可能导致timeout耗尽误判超时。

**修复**：适当增大 `SDMMC_DATATIMEOUT`（默认0x00FFFFFF）

## 附录D：AVI视频解码流程

### D.1 AVI文件格式与数据结构

该工程只支持**MJPG编码**的AVI文件。AVI文件结构如下：

```
AVI文件
├── RIFF头（AVI_HEADER）
│   ├── RiffID: "RIFF" (0x46464952)
│   └── AviID:  "AVI " (0x20495641)
│
├── LIST "hdrl"（信息块）
│   ├── AVIH（AVIH_HEADER）：帧间隔、总帧数等
│   └── LIST "strl"（流信息块，可能有视频流+音频流）
│       ├── STRH（STRH_HEADER）：流类型(vids/auds)、编码器(MJPG)
│       └── STRF（STRF_BMPHEADER/STRF_WAVHEADER）：分辨率、采样率等
│
└── LIST "movi"（数据块）
    ├── "00dc" + 帧数据（视频帧）
    ├── "01wb" + 帧数据（音频帧）
    ├── "01dc" + 帧数据（视频帧，交替编号）
    └── "00wb" + 帧数据（音频帧，交替编号）
```

### D.2 核心数据结构

```c
// 全局AVI信息
AVI_INFO g_avix;   // AVI文件解析后的关键信息

typedef __PACKED_STRUCT {
    uint32_t SecPerFrame;       // 每帧间隔时间(us)
    uint32_t TotalFrame;        // 总帧数
    uint32_t Width;             // 视频宽度
    uint32_t Height;            // 视频高度
    uint32_t SampleRate;        // 音频采样率
    uint16_t Channels;          // 音频通道数
    uint16_t AudioBufSize;      // 音频缓冲区大小
    uint16_t AudioType;         // 音频格式：0x0001=PCM, 0x0055=MP3
    uint16_t StreamID;          // 流ID：0x6463=视频(dc), 0x7762=音频(wb)
    uint32_t StreamSize;        // 当前流数据大小（必须为偶数）
    char *VideoFLAG;            // 视频帧标记："00dc"或"01dc"
    char *AudioFLAG;            // 音频帧标记："00wb"或"01wb"
} AVI_INFO;
```

### D.3 avi_init() — AVI文件解析流程

```c
AVISTATUS avi_init(uint8_t *buf, uint32_t size)
{
    // 步骤1：验证RIFF头
    aviheader = (AVI_HEADER *)buf;
    if (aviheader->RiffID != AVI_RIFF_ID) return AVI_RIFF_ERR;  // "RIFF"
    if (aviheader->AviID  != AVI_AVI_ID)  return AVI_AVI_ERR;   // "AVI "

    // 步骤2：跳过AVI_HEADER，找到LIST头
    buf += sizeof(AVI_HEADER);
    listheader = (LIST_HEADER *)buf;
    if (listheader->ListID   != AVI_LIST_ID) return AVI_LIST_ERR; // "LIST"
    if (listheader->ListType != AVI_HDRL_ID) return AVI_HDRL_ERR; // "hdrl"

    // 步骤3：读取AVIH，获取帧时间和总帧数
    buf += sizeof(LIST_HEADER);
    avihheader = (AVIH_HEADER *)buf;
    g_avix.SecPerFrame = avihheader->SecPerFrame;
    g_avix.TotalFrame  = avihheader->TotalFrame;

    // 步骤4：跳过AVIH，查找strl列表
    buf += avihheader->BlockSize + 8;
    listheader = (LIST_HEADER *)buf;
    // 检查 strl

    // 步骤5：读取STRH，判断流类型
    strhheader = (STRH_HEADER *)(buf + 12);

    if (strhheader->StreamType == AVI_VIDS_STREAM) {
        // 视频流在前，音频流在后（标准顺序）
        if (strhheader->Handler != AVI_FORMAT_MJPG) return AVI_FORMAT_ERR;
        // 非MJPG格式，不支持！

        g_avix.VideoFLAG = "00dc";
        g_avix.AudioFLAG = "01wb";

        // 读取STRF_BMPHEADER获取视频分辨率
        bmpheader = (STRF_BMPHEADER *)(buf + 12 + strhheader->BlockSize + 8);
        g_avix.Width  = bmpheader->bmiHeader.Width;
        g_avix.Height = bmpheader->bmiHeader.Height;

        // 继续读取音频流STRF_WAVHEADER...
        // 获取SampleRate, Channels, AudioType
    }
    else if (strhheader->StreamType == AVI_AUDS_STREAM) {
        // 音频流在前，视频流在后（非标准顺序，但也支持）
        g_avix.VideoFLAG = "01dc";
        g_avix.AudioFLAG = "00wb";
        // 类似上面逻辑，但先读音频STRF，再读视频STRF
    }

    // 步骤6：查找movi数据块起始位置
    offset = avi_srarch_id(tbuf, size, "movi");
    if (offset == 0) return AVI_MOVI_ERR;

    // 步骤7：如果有音频，查找音频帧大小
    if (g_avix.SampleRate) {
        offset = avi_srarch_id(tbuf + offset, size, g_avix.AudioFLAG);
        tbuf  += offset + 4;
        g_avix.AudioBufSize = *((uint16_t *)tbuf);
    }

    return AVI_OK;
}
```

### D.4 avi_get_streaminfo() — 单帧信息提取

```c
AVISTATUS avi_get_streaminfo(uint8_t *buf)
{
    g_avix.StreamID   = MAKEWORD(buf + 2);    // 流类型：dc(视频) / wb(音频)
    g_avix.StreamSize = MAKEDWORD(buf + 4);   // 帧数据大小

    // 帧大小检查：不能超过AVI_MAX_FRAME_SIZE (260KB)
    if (g_avix.StreamSize > AVI_MAX_FRAME_SIZE) {
        printf("FRAME SIZE OVER:%d\r\n", g_avix.StreamSize);
        return AVI_STREAM_ERR;
    }

    // 补齐到偶数（AVI规范要求）
    if (g_avix.StreamSize % 2) g_avix.StreamSize++;

    return AVI_OK;
}
```

### D.5 AVI视频播放流程（videoplay.c中的典型逻辑）

```
打开AVI文件
  → 读取头部到缓冲区（avi_init解析）
  → 循环播放每一帧：
      ├─ 查找下一帧标记（"00dc"/"01dc" for 视频, "00wb"/"01wb" for 音频）
      ├─ avi_get_streaminfo() 获取帧大小和类型
      ├─ 如果是视频帧：
      │   └─ mjpeg_decode(buf, stream_size)  → JPEG硬件解码
      │       → DMA2D YUV→RGB转换
      │       → 填充到LCD显示缓冲
      ├─ 如果是音频帧：
      │   └─ 发送到ES8388音频输出（SAI+I2S）
      └─ 根据SecPerFrame延时到下一帧
```

### D.6 AVI解码常见Bug

| 现象 | 原因 | 解决 |
|------|------|------|
| "RIFF ID错误" | 文件头损坏或非AVI | 重新转换视频 |

## 附录E：JPEG硬件解码流程

### E.1 JPEG解码硬件资源

STM32H743内置**硬件JPEG编解码器**（JPEG Codec），配合**MDMA**（主DMA）实现高效JPEG解码。

**涉及的硬件模块**：
- **JPEG**：硬件JPEG解码器
- **MDMA**：主DMA，负责数据输入/输出传输
- **DMA2D**：2D图形加速器，负责YUV→RGB色彩空间转换

### E.2 核心数据结构

```c
    jpeg_databuf_type outbuf[JPEG_DMA_OUTBUF_NB];   // 输出缓冲（2个，双缓冲）
```

### E.3 mjpeg_jpeg_core_init() — JPEG硬件初始化

```c
uint8_t mjpeg_jpeg_core_init(jpeg_codec_typedef *tjpeg)
{
    // 1. 使能JPEG硬件时钟
    RCC->AHB3ENR  |= 1 << 5;

    // 2. 复位JPEG硬件
    RCC->AHB3RSTR |= 1 << 5;
    RCC->AHB3RSTR &= ~(1 << 5);

    // 3. 使能JPEG外设
    JPEG->CR = 0;
    JPEG->CR |= 1 << 0;    // 使能硬件JPEG

    // 4. 停止当前解码
    JPEG->CONFR0 &= ~(1 << 0);

    // 5. 清空输入/输出FIFO
    JPEG->CR |= 1 << 13;   // 清输入FIFO
    JPEG->CR |= 1 << 14;   // 清输出FIFO

    // 6. 清除标志
    JPEG->CFR = 3 << 5;

    // 7. 配置中断（抢占1，子优先级3）
    sys_nvic_init(1, 3, JPEG_IRQn, 2);

    // 8. 使能Header解析中断
    JPEG->CONFR1 |= 1 << 8;  // 使能header解码完成中断

    return 0;
}
```

### E.4 mjpeg_decode() — 完整解码流程

```c
uint8_t mjpeg_decode(uint8_t *buf, uint32_t bsize)
{
    // ===== 步骤1：设置输入数据 =====
    mjpeg.inbuf[0].buf  = buf;     // JPEG原始数据
    mjpeg.inbuf[0].size = (bsize > JPEG_DMA_INBUF_LEN) ? JPEG_DMA_INBUF_LEN : bsize;
    mjpeg_remain_size   = bsize;   // 剩余未传输数据

    // ===== 步骤2：初始化输出缓冲 =====
    for (int i = 0; i < JPEG_DMA_OUTBUF_NB; i++) {
        mjpeg.outbuf[i].buf  = mymalloc(SRAMIN, yuv_output_size);
        mjpeg.outbuf[i].sta  = 0;
    }

    // ===== 步骤3：注册回调函数 =====
    jpeg_in_callback  = mjpeg_dma_in_callback;   // 输入数据用完时回调
    jpeg_out_callback = mjpeg_dma_out_callback;  // 输出数据就绪时回调
    jpeg_eoc_callback = mjpeg_endofcovert_callback; // 解码完成回调
    jpeg_hdp_callback = mjpeg_hdrover_callback;     // Header解析完成回调

    // ===== 步骤4：启动MDMA输入传输 =====
    jpeg_in_dma_init((uint32_t)mjpeg.inbuf[0].buf, mjpeg.inbuf[0].size);
    jpeg_in_dma_start();

    // ===== 步骤5：主循环处理输出数据 =====
    while (1) {
        // 等待输出缓冲就绪
        if (mjpeg.outbuf[read_ptr].sta == 1) {
            // YUV → RGB565转换（DMA2D硬件加速）
            if (lcdltdc.pwidth == 0) {
                // MCU屏：先转到中间缓冲rgb565buf，再写LCD GRAM
                jpeg_dma2d_yuv2rgb_conversion(&mjpeg, (uint32_t*)rgb565buf);
                // 然后填充到LCD
                mjpeg_fill_color(...);
            } else {
                // RGB屏（LTDC）：直接DMA2D转换到LCD帧缓冲
                mjpeg_ltdc_dma2d_yuv2rgb_fill(offx, offy + curheight, &mjpeg);
            }

            // 标记缓冲已消费
            mjpeg.outbuf[read_ptr].sta = 0;
            read_ptr = (read_ptr + 1) % JPEG_DMA_OUTBUF_NB;

            // 检查是否全部解码完成
            if (mjpeg.yuvblk_curheight >= mjpeg.Conf.ImageHeight) break;
        }

        // 处理输出DMA暂停恢复（双缓冲切换时）
        if (mjpeg.outdma_pause == 1 && outbuf[write_ptr].sta == 0) {
            jpeg_out_dma_resume(buf_addr, yuvblk_size);
            mjpeg.outdma_pause = 0;
        }

        // 检查错误
        if (mjpeg.state == JPEG_STATE_ERROR) break;

        // 检查解码完成
        if (mjpeg.state == JPEG_STATE_FINISHED) {
            // 验证输出高度是否完整
            if (mjpeg.yuvblk_curheight < mjpeg.Conf.ImageHeight) {
                // 高度不足但解码已完成 = 异常
                if (diff > 16) {  // 允许16行的误差
                    mjpeg.state = JPEG_STATE_ERROR;
                    break;
                }
            }
        }

        // 超时保护
        if (++timecnt > 0x3FFFF) { printf("failed\r\n"); break; }
    }

    return 0;
}
```

### E.5 回调函数详解

#### mjpeg_dma_in_callback() — 输入数据供给

```c
void mjpeg_dma_in_callback(void)
{
    if (mjpeg_remain_size) {
        // 还有剩余数据需要传输
        mjpeg.inbuf[0].buf += JPEG_DMA_INBUF_LEN;  // 偏移4KB
        if (mjpeg_remain_size < JPEG_DMA_INBUF_LEN) {
            // 最后一小块，一次传完
            mjpeg.inbuf[0].size = mjpeg_remain_size;
            mjpeg_remain_size = 0;
        } else {
            // 继续分块传输，每次4KB
            mjpeg.inbuf[0].size = JPEG_DMA_INBUF_LEN;
            mjpeg_remain_size -= JPEG_DMA_INBUF_LEN;
        }
        jpeg_in_dma_resume(buf_addr, size);  // 继续DMA传输
    } else {
        mjpeg_fileover = 1;  // 全部传输完毕
    }
}
```

#### mjpeg_dma_out_callback() — 输出数据接收

```c
void mjpeg_dma_out_callback(void)
{
    // 标记当前输出缓冲为就绪状态
    mjpeg.outbuf[mjpeg.outbuf_write_ptr].sta  = 1;
    mjpeg.outbuf[mjpeg.outbuf_write_ptr].size = yuvblk_size;

    // 更新当前已解码高度
    mjpeg.yuvblk_curheight += mjpeg.yuvblk_height;

    // 写指针移到下一个缓冲
    mjpeg.outbuf_write_ptr++;
    if (mjpeg.outbuf_write_ptr >= JPEG_DMA_OUTBUF_NB)
        mjpeg.outbuf_write_ptr = 0;

    // 如果还有高度需要解码，恢复输出DMA
    if (mjpeg.yuvblk_curheight < mjpeg.Conf.ImageHeight) {
        // 指向下一个缓冲地址
        jpeg_out_dma_resume(next_buf_addr, yuvblk_size);
    } else {
        mjpeg.outdma_pause = 1; // 暂停输出DMA
    }
}
```

### E.6 YUV→RGB色彩空间转换

#### DMA2D方式（硬件加速）

```c
// MCU屏：两步走
jpeg_dma2d_yuv2rgb_conversion(&mjpeg, (uint32_t*)rgb565buf);
// 1. DMA2D将YUV数据转换为RGB565存入中间缓冲
// 2. 再将RGB565缓冲写入LCD GRAM（DMA或逐点写入）

// LTDC RGB屏：一步到位（更快）
mjpeg_ltdc_dma2d_yuv2rgb_fill(offx, offy + curheight, &mjpeg);
// DMA2D直接从YUV缓冲转换到LCD帧缓冲地址
```

#### 关键参数 — yuvblk_size计算

```c
// YUV420（4:2:0）：每个像素1.5字节，每次处理16行
yuvblk_size   = ImageWidth * 16 * 1.5;  // 16行高
yuvblk_height = 16;

// YUV422（4:2:2）：每个像素2字节，每次处理8行
yuvblk_size   = ImageWidth * 8 * 2;
yuvblk_height = 8;

// YUV444（4:4:4）：每个像素3字节，每次处理8行
yuvblk_size   = ImageWidth * 8 * 3;
yuvblk_height = 8;
```

### E.7 JPEG解码常见Bug

| 现象 | 原因 | 解决 |
|------|------|------|
| 解码无输出 | JPEG头解析失败 | 检查JPEG文件完整性、CONFR1 header中断使能 |
| 花屏/颜色错误 | YUV色彩空间/采样格式不匹配 | 检查ColorSpace和ChromaSubsampling值 |
| 图片只显示一部分 | yuvblk_curheight计算错误 | 检查out_callback中的高度累加逻辑 |
| 解码超时"failed" | 图片太大或时钟太慢 | 增大超时计数值或降低分辨率 |
| 内存分配失败 | 输出缓冲不够大 | 减小JPEG_DMA_OUTBUF_NB或增大缓冲 |
| 输入数据卡住 | input_callback未触发 | 检查MDMA通道配置和中断优先级 |
| RGB屏显示异常 | LTDC帧缓冲地址不对 | 检查g_ltdc_framebuf指针是否正确 |
| MCU屏显示慢 | 两次拷贝（YUV→RGB→LCD） | 改用LTDC RGB屏或优化DMA2D路径 |
| DMA2D转换无输出 | CSS参数与JPEG采样率不匹配 | 确认ChromaSubsampling值对应DMA2D_CSS设置 |

## 16. PPC 移植修复记录

### 16.1 SD 卡 4bit 模式启用 + 时钟修复

**日期**：2026-06-16

**问题**：SD 卡仅工作在 1-bit 模式，尝试启用 4-bit 后初始化卡死 ~30s。

**根因**：
- CubeMX 生成 `BusWide = SDMMC_BUS_WIDE_1B`，需改为 `SDMMC_BUS_WIDE_4B`
- PLL2 → SDMMCCLK = 150MHz，`ClockDiv = 0` 导致 UHS-I 卡保持在 75MHz
- 4 线数据 @75MHz 超出信号完整性极限，HAL_SD_ReadBlocks 频繁失败触发重试

**修复**（`Core\Src\sdmmc.c`）：
```c
hsd1.Init.BusWide = SDMMC_BUS_WIDE_4B;   // 原 SDMMC_BUS_WIDE_1B
hsd1.Init.ClockDiv = 2;                   // 原 0，SDMMC_CK = 150MHz/(2+2) = 37.5MHz
```
参考正点原子 `SDMMC_TRANSFER_CLK_DIV = 3`（200MHz → 40MHz）。

### 16.2 JPEG/AVI 解码 AHB3 总线竞争修复

**日期**：2026-06-16

**问题**：AVI 视频播放和快速切图时出现 `failed`（JPEG 硬解码超时），`mjpeg.c:442`。

**根因**：
JPEG 硬解码的 MDMA 输入通道从 `g_file_content[64KB]` 读取数据，该缓冲区位于 AXI SRAM (0x24000000, AHB3 总线)。MDMA 与 SDMMC1 同在 AHB3 矩阵，产生总线竞争导致 MDMA 被阻塞，JPEG 解码管道 stall 超时。

**内存分析**：

| 区域 | 地址 | 容量 | 修复前占用 | 修复后占用 | 总线 |
|------|------|------|-----------|-----------|------|
| DTCM | 0x20000000 | 128KB | 54.1KB (42.3%) | 118.1KB (92.3%) | TCM |
| AXI SRAM | 0x24000000 | 512KB | 502.6KB (98.2%) | 438.6KB (85.7%) | AHB3 |
| SDRAM | 0xC0000000 | 32MB | LCD 帧缓冲 + 缓存 | 不变 | FMC |
| 内部 Flash | 0x08000000 | 2MB | 1446KB (70.6%) | 不变 | AXI |

**修复**：
1. 散列文件 `MDK-ARM/H743_LCD_Keil5/H743_LCD_Keil5.sct` 增加 DTCM 专属 section：
```
RW_IRAM1 0x20000000 0x00020000  {  ; RW data (DTCM)
   *(.bss.avi_jpeg_inbuf)           ; AVI/JPEG 输入缓冲，避开 AHB3
   .ANY (+RW +ZI)
}
```

2. `lvgl_GUI/generated/events_init.c:477` — 变量声明加段属性：
```c
static char g_file_content[65536] __attribute__((section(".bss.avi_jpeg_inbuf")));
```

MDMA 通过 AHBS 访问 DTCM，不再经过 AHB3，彻底消除与 SDMMC1 的总线竞争。此方案参考了正点原子 `mymalloc(SRAMDTCM, ...)` 的设计。

### 16.3 SD 卡 4bit + 缓冲迁移联合效果
